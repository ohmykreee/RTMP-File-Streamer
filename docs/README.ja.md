ローカルの動画をプレイリスト順に連続配信するデスクトップアプリです。動画（外部字幕・内蔵字幕に対応）を設定に従って再エンコードして配信します。ローカルのライブラリを 24 時間チャンネルとして流すのに向いています。RTMP / RTMPS、SRT、RTSP、WebRTC（WHIP）に対応しています。

## インターフェース

| エリア | 内容 |
|---|---|
| プレイリスト | 「+ 動画」またはファイルのドラッグで追加。並べ替え、項目の削除、一括クリア。各行に状態と字幕の入口を表示 |
| 設定 | 映像エンコード / 音声エンコード / 字幕 / 配信 / 詳細 の 5 タブ。上部にプリセットバー |
| 再生エリア | プレイリスト全体の進行バー、現在のファイルと位置、エンコードとネットワークの統計、開始 / 停止 / 次のファイル |
| 実行ログ | 下部パネル。レベルで絞り込み、自動スクロール、クリアが可能 |

プレイリストと設定の間の仕切りはドラッグできます。言語ボタンはトップバーの右端にあり、「詳細 → インターフェース」にも同じ言語と外観の設定があります。

## インストール

1. 各プラットフォームのアーカイブをダウンロードし、**書き込み可能なフォルダ**に展開します（`C:\Program Files` などの読み取り専用の場所は避けてください）。
2. 実行します：Windows は `RTMPFileStreamer.exe`、Linux は展開先の `rtmp-file-streamer`、macOS は `RTMP File Streamer.app`。
3. 状態はすべてアプリフォルダ内の `Data/` に保存されます。フォルダごと USB メモリにコピーまたは移動できます。
4. FFmpeg + FFprobe が必要です（「動作環境」参照）。FFmpeg は同梱していません。アプリフォルダの `bin/`（パッケージ版は `resources/bin/`）に `ffmpeg` / `ffprobe` を置くこともできます。

## クイックスタート

1. 起動し、右上に FFmpeg のバージョンが表示されることを確認します。「FFmpeg が見つかりません」と表示されたら「詳細」でパスを指定します。
2. 「配信」タブでプロトコルを選び、アドレスとストリームキー（任意）を入力して「接続をテスト」をクリックします。
3. 「映像エンコード」などのタブで設定を調整するか、内蔵プリセットを選びます。決まったら「プリセットとして保存」をクリックします。
4. 「+ 動画」でファイルを追加（複数選択可）するか、プレイリストにドラッグします。同じフォルダの同名字幕は自動で関連付けられます。
5. 必要に応じて各項目の字幕と同期の設定を展開し、字幕トラック、処理方法、遅延を選びます。
6. 「配信を開始」（または `Space`）をクリックします。配信中は進行バーをドラッグして移動したり、「次のファイル」をクリックできます。「停止」で終了します。

## プレイリストと字幕

- 各ファイルの長さ、解像度、フレームレート、音声・映像トラック、内蔵字幕トラックを自動で読み取ります。
- 同じフォルダの同名字幕を自動で関連付けます：`movie.srt`、`movie.zh-CN.ass`、`movie.forced.srt`、および `Subs/`、`字幕/` サブフォルダ。
- 行ごとに字幕トラック（内蔵 #N / 外部ファイル）、字幕の処理、音声・映像の遅延、字幕の遅延を個別に設定できます。
- 対応する外部字幕：`.srt` `.ass` `.ssa` `.vtt` `.sub` `.idx` `.sup`。テキスト字幕は焼き込みできます。`.sup` / `.idx` などのビットマップ字幕は検出・関連付けできますが、**焼き込みはできません**。アプリが警告してスキップします。
- 各行の状態：配信待ち / 準備中 / 配信中 / 完了 / スキップ / エラー。状態は**視聴者がどこまで見ているか**を表し、エンコーダーの位置ではありません。エンコードは先行して進むため、エンコード済みでも未配信のファイルは「準備中」と表示されます。
- プレイリストとすべての設定は自動保存され、次回起動時に復元されてファイルが再検証されます。ドラッグに混ざった動画以外のファイルは無視され、ログに記録されます。

## エンコードとプリセット

| 分類 | 設定項目 |
|---|---|
| 映像 | H.264 / H.265 / AV1 / そのままコピー。エンコーダー（ハードウェアを自動優先、AMF / NVENC / QSV / libx264 / libx265 / SVT-AV1 / libaom を指定可）。CBR / VBR / ABR / CRF。ビットレート、最大ビットレート、バッファサイズ、CRF、preset、tune、profile、解像度、フレームレート、キーフレーム間隔、B フレーム数、ピクセルフォーマット |
| 音声 | AAC / MP3 / Opus / コピー / 音声なし。ビットレート、サンプルレート、チャンネル数、CBR / VBR、ラウドネス正規化（loudnorm −16 LUFS） |
| 字幕 | オフ / 映像に焼き込む / 独立したトラックとしてコピー。スタイルの取得元（元の ASS スタイルを保持 / 強制上書き / プレーンテキスト）、フォント、サイズ、色、縁取り、影、垂直余白、配置、太字 / 斜体 |

**解像度**：「出力をスケーリング」をオフにするとソース解像度を維持します。オンにすると幅と高さを入力するか、4K / 2K / 1080p / 900p / 720p / 480p / 360p から選びます。幅と高さは自動で偶数に丸められます。「高さを自動調整」にチェックすると、FFmpeg がソースのアスペクト比から高さを計算します。

**ビットレートの単位**：映像ビットレート、最大ビットレート、バッファサイズには `kbps / Mbps` のドロップダウンがあります。音声ビットレートは kbps で入力します。

**CRF**：最大ビットレートは上限として有効で、配信ビットレートが暴走しないようにします。

プリセットバーにはドロップダウン（内蔵プリセット / マイプリセット）と「プリセットとして保存」「名前変更」「削除」「データディレクトリ」があります。

- 保存時は「映像エンコード」「音声エンコード」「字幕」「配信」の 4 タブの設定を 1 つの名前付きプリセットに書き込みます。「詳細」タブの言語、外観、ログ、FFmpeg パスはプリセットに含まれません。
- 内蔵プリセットはエンコード関連の設定だけを変更し、配信アドレス、ストリームキー、obs-websocket の設定は上書きしません。
- **ユーザープリセットは構成全体を復元**し、配信先も平文で保存します。
- 同じ名前で保存すると上書きされます。手動で設定を変更すると、ドロップダウンは「（カスタム）」に戻ります。
- 名前変更は名前だけを変えます。プリセット ID、内容、現在の選択状態は変わりません。内蔵プリセットは名前変更も削除もできません。

## 配信

プロトコルによってアドレス形式、コンテナ、ストリームキーの扱いが決まります：

| プロトコル | アドレスの例 | ストリームキーの用途 |
|---|---|---|
| RTMP / RTMPS | `rtmp://live.example.com/app/` | アドレスの末尾にそのまま追加 |
| SRT | `srt://live.example.com:9000` | アドレスの末尾にそのまま追加。暗号化する場合はパスフレーズをストリームキー欄に入力 |
| RTSP | `rtsp://live.example.com:8554/live` | アドレスのパスにそのまま追加 |
| WebRTC / WHIP | `https://live.example.com/whip/endpoint` | Bearer トークンとして送信 |

- アドレス欄は**フォーカスを外したときにプロトコルを自動判定**し、ドロップダウンを切り替えます。判定後も手動で変更できます。アドレスとプロトコルが一致しない場合は開始もテストもできません。
- アドレスと数値の欄はフォーカスを外したときに反映されます。ストリームキー、追加引数、テキスト、色は即時反映です。
- アドレスは空のままでもかまいません。空のときは「配信を開始」が無効になり、サンプルアドレスが勝手に戻ることはありません。
- ストリームキーの欄は伏せ字で表示されます（「表示」で一時的に確認できます）。キーはローカル設定とプリセットに平文で保存されますが、**画面とログに完全な配信先は表示されません**（サーバーアドレスのみ、キーは `***` に置き換え）。
- コンテナはプロトコルから自動で決まります（RTMP → FLV、SRT → MPEG-TS、RTSP / WHIP はそれぞれのプロトコル）。コンテナの個別設定はありません。
- **接続をテスト**は現在のエンコード設定で 5 秒のテスト映像を配信し、サーバーの応答そのものと診断結果を表示します。サーバーが応答しない場合は時間どおりに終了します。
  - テストは実際の配信と同じエンコーダー、レート制御、サンプルレート、チャンネル数、ラウドネス正規化、フレームレート、キーフレーム間隔、ピクセルフォーマット、プロトコル、カスタム引数を使用します。
  - テスト映像は合成映像です。スケーリングがオンのときは目標サイズで生成し、最大 1280×720 に抑えます。オフのときは 640×360 です。映像 / 音声が「そのままコピー」または「音声なし」の場合はコピー元がないため、ソフトウェアエンコードに戻るか、実際に音声トラックを送りません。字幕の焼き込みとコピーはテスト対象外です。相違点は結果に表示されます。
- **FFmpeg コマンドを表示**は現在の設定から生成したコマンドラインをコピーできます。バッファ配信がオンのときは実際にはエンコーダーと配信プロセスの 2 つが動きますが、プレビューには同等の単一プロセス版を表示し、その旨を明記します。
- 切断時の自動再接続（回数 / 間隔を設定可能）：単一プロセスでは切断点付近から再開します。バッファ配信では視聴者が現在見ている位置からセッションを再構築します。
- **配信中は設定とプレイリストの編集がロックされます**：設定パネル、プリセットバー、プレイリストの追加 / 並べ替え / クリア / 字幕編集は凍結されます。移動、スキップ、停止、ログの表示は引き続き使え、停止すると自動で解除されます。

### よく使うアドレス

| プラットフォーム / プロトコル | アドレス形式 |
|---|---|
| ローカルの nginx-rtmp / SRS（RTMP） | `rtmp://127.0.0.1/live/` + 任意のキー |
| YouTube Live（RTMP） | `rtmp://a.rtmp.youtube.com/live2/` + ストリームキー |
| Twitch（RTMP） | `rtmp://live.twitch.tv/app/` + ストリームキー |
| ビリビリ（RTMP） | `rtmp://live-push.bilivideo.com/live-bvc/` + ストリームキー（`?` パラメーターを含む。キー欄に全体を貼り付け） |
| SRT 受信側 | `srt://receiver.example.com:9000` + パスフレーズ（キー欄に入力） |
| RTSP サーバー | `rtsp://receiver.example.com:8554/live` + キー（サーバーの指定に従う） |
| WHIP エンドポイント | `https://receiver.example.com/whip/endpoint` + トークン |

> RTMP / RTSP の最終的な配信先は、アドレスそのまま + キーそのままです（アプリは区切り文字を挿入しません）。アドレスの末尾に `/` を付けるかどうかはプラットフォームの指定に従ってください。

## バッファ配信

- 既定でオンです。エンコーダーは全速で進み、配信側は 1× で出力します。エンコーダーは「エンコード先行量」（12–300 秒）まで先行でき、それを超えると一時停止します。
- 先行した秒数はすべてメモリに保持されるため、先行量が大きいほどメモリを使います。下限の 12 秒は、ファイル切り替え自体に数秒かかるためです。これより小さいとファイルの境界ごとに配信が途切れます。
- オンのときは進行バー下端の細い緑色のバーがエンコード位置を示します。オフのときはファイルごとに配信セッションを開き直し、「リアルタイムペース配信」と「遅延フレームを破棄」はそのときだけ有効になります。

## 進行状況と移動

- プレイリスト**全体**が 1 本の進行バーとして描画されます。ファイルごとに 1 セグメントで、配信済みの区間は緑、配信中の区間は強調表示され、区間の間には区切り線が入ります。
- **ドラッグできます**：ドラッグ中は移動先のファイル名だけを表示し、離すとそのファイルの**先頭**へ移動します。ライブ配信では送信済みのフレームを取り消せず、アプリはファイル内シークも提供しません。現在のファイル内で離した場合は何も起きません。
- バッファ配信がオンのときは、進行バーの下端に**細い緑色のバー**が表示され、エンコードがどこまで進んだかを示します。青いバーとの距離がエンコード先行量で、移動時に破棄される量でもあります。
- **次のファイル**は次のセグメントへすぐ切り替えます（ショートカット `Ctrl+→`）。
- 各行の右側のアイコンボタンは左から順に、このファイルから配信を開始 / このファイルへ移動、字幕と同期の設定、削除です。
- バーの下の表示：現在のファイルと位置 / 長さ、エンコード速度 / ビットレート / fps、バッファ先行量、実測ネットワーク速度、ドロップフレーム、経過時間。待機中は表示されません。
- 配信が終了すると（プレイリストの最後まで再生、または手動停止）、進行状況は 0 に戻ります。

## 言語、外観、ログ

- トップバー右端の言語ボタン（地球アイコン + 現在の言語コード）に 中文 / 日本語 / English が並び、現在の項目にチェックが付きます。「詳細 → インターフェース」にも同じ選択があります。
- 初回起動時はシステム言語に従います：中国語（簡体字または繁体字）→ 中国語、日本語 → 日本語、**それ以外はすべて英語**。
- 明示的に切り替えると即時反映・保存され、以後はシステム言語に従いません。明示的に切り替えていない間は、起動のたびにシステム言語に従います。言語は画面、ウィンドウタイトル、ネイティブのファイルダイアログ、実行ログとエラーメッセージに反映されます。
- **外観**：ライト / ダーク / システムに従う（既定）。「システムに従う」では OS のライト / ダーク設定にリアルタイムで追従し、ウィンドウの背景色も変わります。言語と外観はアプリの設定であり、プレイリストにもプリセットにも書き込まれません。
- 実行ログパネルはデバッグ / 情報 / 警告 / エラー / FFmpeg で絞り込め、自動スクロールとクリアができます。絞り込みに一致がない場合はその旨を表示します。
- **ログの保存**：`Data/Logs/session-*.log` に書き込みます。1 ファイルが 4 MB を超えると新しいファイルに切り替わり、合計が 12 MB を超えるかファイル数が 20 を超えると、最も古いファイルから削除されます。
- ハードウェアエンコーダーは**実際に数フレームをエンコードして**利用可能かを確認します。名前を列挙するだけではありません。
- ショートカット：`Space` で配信開始（フォーカスがボタン / スイッチ / 入力欄にあるときは奪いません）、`Ctrl+→` で次のファイル。配信中にウィンドウを閉じると、停止して閉じるか配信を続けるかを確認します。

## 動作環境

| 依存関係 | 説明 |
|---|---|
| **FFmpeg + FFprobe** | 必須。検索順：設定で指定したパス → アプリフォルダの `bin/`（パッケージ版は `resources/bin/`）→ `PATH` → 一般的なインストール先。字幕フィルターに対応した完全版を使用してください。対応していないとテキスト字幕を焼き込めません。 |
| オペレーティングシステム | Windows 10/11 x64（検証済み）。macOS / Linux にも対応。Windows / Linux の arm64 版と macOS の Apple シリコン版も提供しています。 |

## 既知の制限

- **移動すると配信セッションを開き直します**：ライブ配信では送信済みのフレームを取り消せません。バッファ内の内容は視聴者がまだ見ていない内容の後ろに並ぶため、破棄してセッションを開き直すしかありません。サーバー側で約 1–3 秒の切断が発生します（視聴者側では再接続として見えます）。実際に破棄される量は「エンコード先行量」の設定に依存し、最大で約 5 分に達します。バッファ配信がオンの場合（既定）、ファイルが最後まで再生されたときはエンコーダーだけを再起動し、視聴者の接続は維持されます。オフの場合はファイルごとに配信セッションを開き直します。
- **エンコード先行量は視聴者の遅延ではありません**：エンコーダーが配信側よりどれだけ先行できるか（12–300 秒）を制限し、エンコードが一時的に遅くなっても配信側が枯渇しないようにするものです。代償はメモリで、先行した秒数はアプリ内に保持されるため、先行量を大きくするほどメモリを使います。下限の 12 秒はファイル切り替えに数秒かかるためで、これより小さいとファイルの境界ごとに配信が途切れます。
- **正の音声・映像遅延は配信の先頭に空白を作ります**：音声・映像の遅延を正の値にすると内容全体が後ろにずれ、配信の先頭にその長さの空白が入ります。音ずれを補正したい場合は負の値（先頭を切り詰める）を推奨します。字幕遅延は焼き込むテキスト字幕にだけ作用します。字幕トラックのコピーやビットマップ字幕では無視され、警告が出ます。
- **ビットマップ字幕は焼き込めません**：内蔵の PGS / DVD / DVB と外部の `.sup` / `.idx` は字幕トラックとしてのみ扱えます。テキスト字幕に切り替えてください。一覧でビットマップトラックを選んで「映像に焼き込む」にすると、パネルにその旨が表示されます。
- **独立した字幕トラックは MPEG-TS など対応するコンテナでのみ使えます**：FLV と WebRTC は独立した字幕トラックを運びません。字幕が必要な場合は「映像に焼き込む」を使用してください。バッファ配信がオンの間は字幕トラックのコピーにも対応していません。
- **コピーはソースのコーデックと出力コンテナの互換性が必要です**：たとえば VP9 / AV1 映像を FLV にコピーする場合や、AC-3 / DTS 音声を FLV にコピーする場合は未対応で、警告が出ます。AV1 映像は MPEG-TS を経由できないため、バッファ配信がオンのときは自動的に単一プロセスに切り替わります。SRT などの MPEG-TS 出力では AV1 に対応していません。
- **Opus は FLV での互換性が低い**：既定は AAC です。Opus を選ぶと警告が出ます。WebRTC（WHIP）では Opus 音声と H.264 映像が必要です。
- **音声トラックや映像トラックがないファイルには自動でトラックを生成します**：ソースに音声がない場合（音声コーデックが「ソース音声をコピー」でも「音声なし」でもないとき）、現在の音声設定で無音をエンコードします。使用可能な映像がない場合（映像コーデックが「そのままコピー」でないとき）、現在の映像設定で黒画面をエンコードします（スケーリングがオフのときは 1280×720）。配信には常に 2 トラックが含まれるため、サーバーに単一トラックとして拒否されません。
- **カバーアートは映像として扱いません**：音楽 / 音声ファイルのアルバムアートはスキップされ、映像として配信されることはありません。ファイル全体がカバーアートだけの場合は、上記のとおり黒画面を配信します。
- **一時停止とファイル内シークはありません**：再開には配信セッションの開き直しが必要で、移動と同じく配信が途切れるため実装していません。`Space` は配信開始にのみ使います。
- **リアルタイムペース配信と遅延フレームの破棄は、バッファ配信がオフのときだけ有効です**：バッファ配信がオンの間、配信側は常に 1× で出力します。画面上でもその旨を説明しています。
- **アプリフォルダには書き込み権限が必要です**：状態はアプリフォルダ内の `Data/` に保存されるため、`C:\Program Files` などの読み取り専用の場所に置かないでください。読み取り専用でも起動はできますが、設定とプリセットを保存できず、ログにエラーが出ます。
- **プレイリストは絶対パスを使います**：アプリフォルダを移動しても設定とプリセットは使えますが、プレイリスト内のファイルはドライブ文字やマシンが変わると無効になり、追加し直す必要があります。

## データとバックアップ

すべての状態（設定 / プレイリスト / プリセット / ログ）は**アプリフォルダ内の `Data` フォルダ**に保存され、通常はシステムのローミング設定ディレクトリを使いません：

| ファイル | 内容 |
|---|---|
| `Data/settings.json` | FFmpeg のパス、画面の言語と外観、プレイリスト欄の幅、現在のセッション設定 |
| `Data/playlist.json` | プレイリスト。次回起動時に自動復元 |
| `Data/presets.json` | ユーザーが保存したプリセット（配信先を平文で含む） |
| `Data/Logs/` | 実行ログの保存 |
| `Data/Cache/` | キャッシュと一時データ |

> `settings.json` と `presets.json` は配信アドレスとストリームキーを平文で保存します。公開したり、リポジトリにコミットしたり、アプリごと他人に渡したりしないでください。

ポータブル版のため、アプリフォルダ全体（`Data/` を含む）を **USB メモリにコピーまたは移動**して、別のマシンで展開してもそのまま使えます。プレイリスト内の絶対パスは有効なままにしておくか、ファイルを追加し直してください。

- **外部の状態は取り込みません**：初回起動時にシステムの他の場所から設定を移すことはなく、すべて新規です。
- **別のマシンで使い続ける**：アプリフォルダ全体をコピーしてください。
- **初期状態に戻す**：`Data/` フォルダを削除すると、次回起動時に再作成されます。
