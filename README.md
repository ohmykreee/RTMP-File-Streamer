---

本地视频按播放列表顺序连续推流的桌面应用。视频（可带外挂或内挂字幕）按你的设置重新编码后推送出去，适合把本地片库当成一个 24 小时频道来播。支持 RTMP / RTMPS、SRT、RTSP 与 WebRTC（WHIP）。

## 界面

| 区域 | 内容 |
|---|---|
| 播放列表 | 「+ 视频」或拖入文件；拖拽排序、逐项删除、一键清空；每项显示状态与字幕入口 |
| 设置 | 视频编码 / 音频编码 / 字幕 / 推流 / 高级 五个选项卡；顶部是预设栏 |
| 播放区 | 整条播放列表的进度条、当前文件与位置、编码与网络统计、开始 / 停止 / 下一个文件 |
| 运行日志 | 底部面板：按级别过滤、自动滚动、可清空 |

播放列表与设置之间的分隔条可以拖动。语言按钮在顶栏最右侧；「高级 → 界面设置」里有同样的语言与外观设置。

## 安装

1. 下载对应平台的压缩包，解压到**可写目录**（不要放在 `C:\Program Files` 这类只读位置）。
2. 运行程序：Windows 是 `RTMPFileStreamer.exe`；Linux 解压后运行目录中的 `rtmp-file-streamer`；macOS 运行 `RTMP File Streamer.app`。
3. 所有状态写在程序目录的 `Data/`；整个文件夹可以复制或移动到 U 盘。
4. 系统里需要有 FFmpeg + FFprobe（见「环境要求」）。程序不打包 FFmpeg；也可以把 `ffmpeg` / `ffprobe` 放进程序目录的 `bin/`（打包版为 `resources/bin/`）。

## 快速开始

1. 启动应用，确认右上角显示 FFmpeg 版本号；显示「未找到 FFmpeg」时到「高级」页指定路径。
2. 在「推流」页选择协议，填入地址与串流密钥（可选），点「测试连接」。
3. 在「视频编码」等页调整参数，或选一套内置预设；调好后点「保存为预设」。
4. 点「+ 视频」添加文件（可多选），或把文件拖进播放列表；同目录同名字幕会自动关联。
5. 需要时展开某一项的字幕与同步设置，选择字幕轨、处理方式与延迟。
6. 点「开始串流」（或按 `空格`）；串流中可拖动进度条跳转、点「下一个文件」；点「停止」结束。

## 播放列表与字幕

- 自动读取每个文件的时长、分辨率、帧率、音视频轨与内挂字幕轨。
- 自动关联同目录同名字幕：`影片.srt`、`影片.zh-CN.ass`、`影片.forced.srt`，以及 `Subs/`、`字幕/` 子目录。
- 每一行可以单独选择字幕轨（内挂第 N 条 / 外挂文件）、字幕处理方式、音视频延迟与字幕延迟。
- 支持 `.srt` `.ass` `.ssa` `.vtt` `.sub` `.idx` `.sup`。文本字幕可以烧录；`.sup` / `.idx` 等位图字幕能识别并关联，但**无法烧录**，应用会警告并跳过。
- 每项状态：待串流 / 准备中 / 推流中 / 已完成 / 已跳过 / 错误。状态描述的是**观众看到了哪一段**，不是编码跑到哪一段：编码会提前跑在前面，已编码但还没播出的显示「准备中」。
- 播放列表与全部设置自动保存，下次启动恢复并重新校验文件。混入拖放的非视频文件会被忽略并记录日志。

## 编码与预设

| 分类 | 可设置项 |
|---|---|
| 视频 | H.264 / H.265 / AV1 / 直接复制；编码器（自动优选硬件，可指定 AMF / NVENC / QSV / libx264 / libx265 / SVT-AV1 / libaom）；CBR / VBR / ABR / CRF；码率、最大码率、缓冲区、CRF、preset、tune、profile、分辨率、帧率、关键帧间隔、B 帧数、像素格式 |
| 音频 | AAC / MP3 / Opus / 复制 / 不要音频；码率、采样率、声道数、CBR / VBR、响度归一化（loudnorm −16 LUFS） |
| 字幕 | 关闭 / 烧录进画面 / 作为独立轨道复制；样式来源（保留原 ASS 样式 / 强制覆盖 / 纯文本）、字体、字号、颜色、描边、阴影、垂直边距、对齐、粗体 / 斜体 |

**分辨率**：关闭「缩放输出」保持源分辨率；打开后填写宽 / 高，或选 4K / 2K / 1080p / 900p / 720p / 480p / 360p。宽高自动取偶；勾选「高度自适应」后高度由 FFmpeg 按源画面比例计算。

**码率单位**：视频码率、最大码率与缓冲区有 `kbps / Mbps` 下拉框，音频码率按 kbps 填写。

**CRF**：最大码率仍然生效，作为码率上限，避免推流码率失控。

预设栏提供下拉选择（内置预设 / 我的预设）与「保存为预设」「重命名」「删除」「数据目录」。

- 保存时把视频、音频、字幕、推流四个选项卡的设置写入一个命名预设；高级页的语言、外观、日志、FFmpeg 路径不进入预设。
- 内置预设只改变编码相关设置，不会覆盖推流地址、串流密钥与 obs-websocket 配置。
- **用户预设会完整还原整组配置**，并明文保存推流目标。
- 同名保存即覆盖；手动改动任意设置后，下拉框回到「（自定义）」。
- 重命名只换名称：预设 id、内容与当前选中状态都不变；内置预设不能重命名或删除。

## 推流

协议决定地址格式、封装与串流密钥的用法：

| 协议 | 地址示例 | 串流密钥的用途 |
|---|---|---|
| RTMP / RTMPS | `rtmp://live.example.com/app/` | 直接追加到地址末尾 |
| SRT | `srt://live.example.com:9000` | 直接追加到地址末尾；加密时把口令写进串流密钥框 |
| RTSP | `rtsp://live.example.com:8554/live` | 直接追加到地址路径 |
| WebRTC / WHIP | `https://live.example.com/whip/endpoint` | 作为 Bearer 令牌发送 |

- 地址框**失焦时自动识别协议**并切换下拉；识别后仍可手动改。地址与协议不匹配时无法开始或测试。
- 地址与数字框在离开输入框时生效；串流密钥、额外参数、文本与颜色即时生效。
- 地址框可以留空，空着时「开始串流」不可用；应用不会自动把示例地址填回去。
- 串流密钥输入框点状显示（可临时「显示」）；密钥明文保存在本地设置与预设中，**界面与日志不显示完整目标**（只显示服务器地址，密钥部分以 `***` 代替）。
- 封装由协议自动决定（RTMP → FLV，SRT → MPEG-TS，RTSP / WHIP 使用各自协议），没有单独的容器选项。
- **测试连接**按当前编码设置推送 5 秒测试画面，给出服务器返回的原文与诊断结论；服务器无响应时按时退出。
  - 测试与正式推流共用编码器、码率控制、采样率、声道数、响度归一化、帧率、关键帧间隔、像素格式、协议与自定义参数。
  - 测试画面是合成画面：启用缩放时按目标尺寸生成并最高压到 1280×720，未启用缩放时用 640×360；视频 / 音频设为「直接复制」或「不要音频」时会回退到软件编码或真的不发音频轨；字幕烧录与复制不在测试范围内。差异会列在结果里。
- **查看 FFmpeg 命令**可复制当前设置生成的命令行。开启缓冲推流时实际运行编码器与推流器两个进程，预览显示等价的单进程命令并注明。
- 断线自动重连（次数 / 间隔可配）：单进程管道在断点附近回退后续传；缓冲推流从观众当前的位置重建会话。
- **串流进行中锁定设置与播放列表编辑**：设置面板、预设栏和播放列表的增删 / 排序 / 清空 / 字幕编辑都会冻结；跳转、跳过、停止与查看日志保持可用，停止后自动解锁。

### 常用地址

| 平台 / 协议 | 地址格式 |
|---|---|
| 本地 nginx-rtmp / SRS（RTMP） | `rtmp://127.0.0.1/live/` + 自定义密钥 |
| YouTube Live（RTMP） | `rtmp://a.rtmp.youtube.com/live2/` + 串流密钥 |
| Twitch（RTMP） | `rtmp://live.twitch.tv/app/` + 串流密钥 |
| 哔哩哔哩（RTMP） | `rtmp://live-push.bilivideo.com/live-bvc/` + 串流密钥（含 `?` 参数，整段填入密钥框） |
| SRT 接收端 | `srt://receiver.example.com:9000` + 口令（写进密钥框） |
| RTSP 服务器 | `rtsp://receiver.example.com:8554/live` + 密钥（按服务器要求） |
| WHIP 端点 | `https://receiver.example.com/whip/endpoint` + 令牌 |

> RTMP / RTSP 的最终目标 = 地址原样 + 密钥原样（应用不插入分隔符），地址结尾是否带 `/` 由平台要求决定。

## 缓冲推流

- 默认开启：编码全速跑，推流按 1× 输出；编码最多领先「编码提前量」（12–300 秒），超过就暂停编码等待。
- 领先的每一秒都暂存在程序里，因此提前量越大内存越多。下限 12 秒是因为换文件本身要几秒，设得更小会在每个文件边界断流。
- 开启时进度条底部的细绿条表示编码进度；关闭后每个文件都会重新开发布会话，「实时节奏」与「丢弃迟到帧」才生效。

## 进度与切换

- 播放列表**整条**渲染为进度条：每个文件一段，已播完的段落变绿，正在播的高亮，段间有分隔线。
- **可拖动**：拖动时只显示目标文件名；松开即跳到该文件的**开头**。直播流无法回退已发送的帧，应用也不提供文件内跳转；在当前文件内松开是空操作。
- 开启缓冲推流时，进度条底边缘有一条**细绿条**，表示编码跑到哪；蓝条与绿条之间的距离是编码提前量，也是跳转要丢弃的部分。
- **下一个文件**立即切到下一段（快捷键 `Ctrl+→`）。
- 每一行右侧的图标按钮，从左到右：从该文件开始串流 / 跳转到此文件、字幕与同步设置、移除。
- 条下方读数：当前文件与位置 / 时长、编码速度 / 码率 / fps、缓冲领先、实测网络速率、丢帧与已运行时长；空闲时不显示。
- 串流结束（播完整个列表或手动停止）后进度归零。

## 语言、外观与日志

- 顶栏最右侧的语言按钮（地球图标 + 当前语言代码）列出 中文 / 日本語 / English，当前项带勾选；「高级 → 界面设置」里也有同一个选择。
- 首次启动按系统语言自动选择：中文（简体或繁体）→ 中文；日语 → 日语；**其他所有语言 → 英文**。
- 显式切换后立即生效并保存，之后不再跟随系统语言；没有显式切换过时，启动继续跟随系统语言。语言覆盖界面、窗口标题、原生文件对话框，以及运行日志与错误提示。
- **界面风格**：亮色 / 暗色 / 跟随系统（默认）。跟随系统时随操作系统的深浅色设置实时切换，窗口底色也一起变。语言与外观属于应用设置，不写入播放列表，也不写入预设。
- 运行日志面板按 调试 / 信息 / 警告 / 错误 / FFmpeg 过滤，可自动滚动与清空；筛选无结果时会单独提示。
- **日志留存**：同步写入 `Data/Logs/session-*.log`。单个文件超过 4 MB 滚动到新文件；总量超过 12 MB 或文件数超过 20 个时自动删除最旧的文件。
- 硬件编码器**实测可用性检测**：真的编码几帧验证驱动能不能用，不只是列出名称。
- 快捷键：`空格` 开始串流（焦点在按钮 / 开关 / 输入框上时不抢占），`Ctrl+→` 下一个文件。串流中关闭窗口会弹出确认：停止并关闭，或继续串流。

## 已知限制

- **跳转会重开一次发布会话**：直播流已发送的帧无法撤回。跳转时缓冲里的内容排在观众还没看的内容后面，只能丢弃并重开一次会话，服务器会有约 1–3 秒断流（观众端表现为一次重连）。实际丢弃量取决于「编码提前量」，最大可接近 5 分钟。默认开启缓冲推流时，文件自然播完只重启编码器，观众连接不受影响；关闭缓冲推流后，每个文件都会重新发布会话。
- **编码提前量不是观众端的延迟**：它限制的是编码最多能超前推流多少秒（12–300），目的是编码偶尔变慢时不让推流端断流。代价是内存 —— 领先的每一秒都暂存在程序里，所以更大的提前量会占更多内存。下限 12 秒是因为换文件本身就要几秒，设得更小会在每个文件边界断流。
- **正数音视频延迟会在流开头留空档**：音视频延迟设为正值时内容整体后移；只想修正音画不同步时建议使用负值（裁剪开头）。字幕延迟只影响烧录的文本字幕；复制字幕轨或位图字幕时该设置会被忽略并给出警告。
- **位图字幕无法烧录**：内挂 PGS / DVD / DVB 与外挂 `.sup` / `.idx` 都只能作为字幕轨处理。请改用文本字幕；在列表中选了位图轨并设为「烧录」时，面板会直接提示。
- **独立字幕轨只在 MPEG-TS 等支持的封装中可用**：FLV 与 WebRTC 不承载独立字幕轨；需要字幕时请使用「烧录进画面」。缓冲推流下也不支持复制字幕轨。
- **直接复制需要源编码与目标封装兼容**：例如 VP9 / AV1 视频复制进 FLV、AC-3 / DTS 音频复制进 FLV 都不受支持；应用会给出警告。AV1 视频也不能经 MPEG-TS 中转，开启缓冲推流时会自动改用单进程，SRT 等 MPEG-TS 目标则不支持 AV1。
- **Opus 在 FLV 中兼容性差**：默认使用 AAC；选择 Opus 时会给出警告。WebRTC（WHIP）则要求 Opus 音频与 H.264 视频。
- **缺少音轨或视频轨的文件会自动补轨**：源文件没有音频（且音频编码不是「直接复制」或「不要音频」）时，按当前音频设置编码一路静音；没有可用视频（且视频编码不是「直接复制」）时，按当前视频设置编码黑场（未开启缩放时用 1280×720）。这样推出去的始终是完整的两路，不会被服务器当成单流拒绝。
- **封面图不算视频**：音乐 / 音频文件的专辑封面会被自动跳过，不会把封面当成画面推出去；整份文件只有封面时按上一条推送黑场画面。
- **没有暂停，也没有文件内跳转**：恢复推流需要重开发布会话，与跳转一样会造成断流，因此不做。快捷键 `空格` 只用于开始串流。
- **实时节奏与丢弃迟到帧只在关闭缓冲推流后生效**：缓冲推流下由推流器固定按 1× 输出，这两个开关在界面上会说明其限制。
- **程序目录必须可写**：状态存在程序目录的 `Data/` 下，不要把它放在只读位置（如 `C:\Program Files`）。放进只读目录时程序仍能运行，但设置与预设无法保存，日志里会给出错误提示。
- **播放列表使用绝对路径**：移动程序文件夹后，设置与预设仍可用，但播放列表里的文件如果换了盘符或机器会失效，需要重新添加。

## 数据与备份

所有状态（设置 / 播放列表 / 预设 / 日志）都写在**程序目录下的 `Data` 文件夹**，正常情况下不使用系统漫游配置目录：

| 文件 | 内容 |
|---|---|
| `Data/settings.json` | FFmpeg 路径、界面语言与界面风格、播放列表栏宽度、当前会话设置 |
| `Data/playlist.json` | 播放列表，下次启动自动恢复 |
| `Data/presets.json` | 用户保存的预设（含明文推流目标） |
| `Data/Logs/` | 运行日志留存 |
| `Data/Cache/` | 缓存与临时数据 |

> `settings.json` 与 `presets.json` 明文保存推流地址和串流密钥，请勿公开分享、上传仓库或随程序一起发给他人。

因为是绿色版，整个程序文件夹（含 `Data/`）可以**复制或移动到 U 盘**，换台机器解压后照常使用；播放列表中的绝对路径需要保持有效，或重新添加文件。

- **不导入任何外部状态**：首次启动不会从系统其它位置搬设置，一切都是新的。
- **换机器继续用**：把整个程序文件夹一起复制过去。
- **恢复出厂设置**：删掉 `Data/` 文件夹，下次启动会重建。
