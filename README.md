# RTMP 文件串流器 (RTMP File Streamer)

本地视频按播放列表顺序连续推流到 RTMP 服务器的桌面应用。视频（可带外挂或内挂字幕）按你的设置重新编码后推送出去，适合把本地片库当成一个 24 小时频道来播。

---

## 1. 功能

### 1.1 选择本地视频与字幕

- 「**+ 视频**」按钮多选视频文件，或把文件**直接拖进**播放列表；混入拖放的非视频文件会被自动忽略并记录日志
- 自动读取每个文件的时长、分辨率、帧率、音视频轨与**内挂字幕轨**
- 自动关联**同目录同名字幕**：`影片.srt`、`影片.zh-CN.ass`、`影片.forced.srt`，以及 `Subs/`、`字幕/` 子目录
- 每个文件可单独选择：使用哪条字幕轨（内挂第 N 条 / 外挂文件）、字幕处理方式、音视频延迟、字幕延迟
- 支持的外挂字幕：`.srt` `.ass` `.ssa` `.vtt` `.sub` `.idx` `.sup`

### 1.2 编码设置

| 分类 | 可设置项 |
| --- | --- |
| **视频** | 编码格式（H.264 / H.265 / AV1 / 直接复制）、编码器（自动优选硬件，可指定 AMF / NVENC / QSV / libx264 / libx265 / SVT-AV1 / libaom）、码率控制（CBR / VBR / ABR / CRF）、码率、最大码率、缓冲区、CRF、preset、tune、profile、**分辨率（宽 / 高两个输入框 + 高度自适应勾选框）**、帧率、关键帧间隔、B 帧数、像素格式、重复 SPS/PPS 头 |
| **音频** | 编码格式（AAC / MP3 / Opus / 复制 / 丢弃）、码率、采样率、声道数、CBR / VBR、响度归一化（loudnorm −16 LUFS） |
| **字幕** | 处理方式（关闭 / **烧录进画面** / 作为独立轨道复制）、样式来源（保留原 ASS 样式 / 强制覆盖 / 纯文本）、字体、字号、颜色、描边、阴影、垂直边距、对齐方式、粗体/斜体 |
| **输出** | 推流地址与协议、串流密钥（可选、点状显示）、推流网络格式、测试连接与命令预览、**双引擎推流开关与「编码缓冲」（12–300 秒）**、实时节奏 `-re`、播放列表循环、断线重连间隔与次数、丢弃迟到帧、追加自定义 ffmpeg 参数、obs-websocket 兼容控制接口 |
| **高级** | **界面设置**（语言、界面风格：亮色 / 暗色 / 跟随系统）、日志留存与**调试输出开关**（关闭后只写 info 及以上）、FFmpeg 路径/版本/编码器可用性 |
| **预设** | 把以上全部设置保存为命名预设；另有 5 套内置预设 |

**码率单位**：所有码率输入框右侧都有 `kbps / Mbps` 下拉框，随手写哪种都行，不会把数值当成另一个数量级。

**分辨率**：

- 关闭「缩放输出」= 保持源分辨率
- 打开后填写**宽度**与**高度**两个框，或从下拉选择预设（4K / 2K / 1080p / 900p / 720p / 480p / 360p）
- 勾选「**高度自适应**」→ 高度框变为禁用并显示「自动」，由 ffmpeg 按源画面比例算好，避免手算非偶数高度导致编码失败

对某个文件单独选轨道：展开它的「字幕与同步设置」，可选内挂第 N 条或指定外挂文件。

#### 预设

- 顶部预设栏：下拉选择（内置预设 / 我的预设分组）+「保存为预设」+「**重命名**」+「删除」+「数据目录」
- **重命名**只换名称：预设 id、里面保存的设置、当前选中状态都不变；内置预设不能重命名、不能删除
- 保存时把**视频、音频、字幕、输出、高级五个选项卡的全部设置**写入一个命名预设
- **推流目标（RTMP 地址与串流密钥）随预设一起明文保存**：套用预设会完整还原整组配置，包括往哪里推流
- 同名保存即覆盖；应用预设会一次性替换全部设置
- 手动改动任意设置后，下拉框自动回到「（自定义）」，不会假装仍匹配某个预设

### 1.3 推流到 RTMP 服务器

- **推流目标 = RTMP 地址 + 串流密钥，直接拼接**（地址按平台要求自带结尾斜杠；**串流密钥可选**，留空则直接推送地址本身）
- 所有输入框都在**离开输入框时**才生效：打字过程中不会被改写。地址框可以留空（下方会提示「地址为空，无法开始串流。」），空着时「开始串流」不可用 —— 不会自动把示例地址填回去
- 串流密钥输入框**点状显示**（可点「显示」临时查看）；密钥明文保存在本地设置与预设中，界面和信息级日志都不显示完整目标
- 输出 FLV，带 `no_duration_filesize`、`+cgop`（关键帧重复 SPS/PPS）、单调时间戳
- 内置 **「测试连接」**：按当前各选项卡的编码设置推送 5 秒测试画面，直接给出服务器返回的原文与诊断结论；服务器无响应时按时退出，不会卡住界面
  - 测试与正式推流**走同一套参数**：编码器、码率控制与码率、采样率、声道数、响度归一化、帧率、关键帧间隔、像素格式、容器、自定义参数都按当前设置生成，所以「测试通过」意味着这组编码参数能推上去，而不只是地址通
  - 测试画面是合成画面，会按当前输出分辨率生成（4K 等大分辨率自动等比压到 720p，保证几秒内出结果）；音视频设为「直接复制」或「不要音频」时在测试里没有可复制的源，会回退到软件编码或真的不发音频轨，这些差异会在结果里列出
- 内置 **「查看 FFmpeg 命令」**：可复制当前设置生成的完整命令行
- 断线自动重连（次数/间隔可配），从断点略微回退后续传
- **串流进行中锁定全部设置**：编码命令在开始时已按当时参数生成，串流中设置面板、预设栏与播放列表的编辑项都会冻结（添加文件、跳转不受影响），停止后自动解锁

### 1.4 串流进度与跳转

- 播放列表**整条**渲染为进度条：每个文件一段，已播完的段落变绿、正在播的高亮，段间有分隔线
- **可拖动**：拖动时显示目标文件名与时间，松开即跳转；松手在**当前文件内是空操作**（直播流无法回退已发送的帧），松手在其它文件上则跳到那个文件
- 开启双引擎推流时，进度条底边缘会多一条**细绿条**，表示编码已经跑到哪。蓝条与绿条之间的距离就是「编码缓冲」，也就是跳转需要丢弃的部分 —— 所以跳转会重开一次 RTMP 会话
- **「下一个文件」** 立即切到下一段（快捷键 `Ctrl+→`）
- 每一行右侧的图标按钮，从左到右是：**从该文件开始串流**、字幕与同步设置、移除（鼠标悬停会显示名称；串流进行中除「开始串流」外都被锁定）。关联外部字幕的按钮在展开的「字幕与同步」面板里
- **控制按钮在它右边**；条下方是一行小字读数：当前文件与位置/时长、编码速度、码率、fps、缓冲领先、实测网络速率、丢帧与重连次数、已运行时长

### 1.5 多文件顺序串流

- 播放列表可拖拽排序、逐项删除、一键清空
- 播放列表与设置之间是**可拖动的分栏**：拖中间的分隔条即可加宽队列
- 播完一个文件后**自动**按顺序进入下一个，直到列表结束（或按设置循环）
- 每项状态实时标注：待串流 / 准备中 / 推流中 / 已完成 / 已跳过 / 错误
  - 这些状态描述的是**观众看到了哪一段**，不是编码跑到哪一段：编码会提前跑在前面，所以已编码但还没播出的文件显示「准备中」
- 播放列表与全部设置**自动保存**，下次启动自动恢复并重新校验文件

### 1.6 界面设置（语言与外观）

- 语言按钮在**顶栏最右侧**（地球图标 + 当前语言代码），点开列出 中文 / 日本語 / English，当前项带勾选；「高级 → 界面设置」里也有同一个语言选择
- **首次启动按系统语言自动选择**：中文（简体或繁体）→ 中文；日语 → 日语；**其他所有语言 → 英文**
- 切换后**立即生效并保存**，之后不再跟随系统语言
- 语言覆盖界面、右键提示、窗口标题、原生文件对话框，以及**运行日志与错误提示**：切换后新的日志行即为所选语言
- **界面风格**：亮色 / 暗色 / **跟随系统（默认）**。「跟随系统」时随操作系统的深浅色设置实时切换，窗口底色也一起变
- 语言与界面风格属于**应用设置**：不写入播放列表，也不写入预设 —— 套用预设不会改变界面语言或外观
- 串流进行中语言与外观设置与其他设置一起锁定

### 1.7 其他

- 运行日志面板（按 信息/警告/错误/FFmpeg 过滤、自动滚动、可清空）
- **日志留存**：全部运行日志同步写入 `Data/Logs/session-*.log`。面板可直接打开日志目录并显示当前占用；总量超过 12 MB 或超过 20 个会话文件时自动删除最旧文件，无需手动清理
- 硬件编码器**实测可用性检测**（不只是列出名称，而是真的编一帧验证驱动能不能用）
- 快捷键：`空格` 开始串流，`Ctrl+→` 下一个文件

## 3. 使用步骤

1. 启动应用，确认右上角显示 FFmpeg 版本号（若显示「未找到 FFmpeg」，到「高级」页手动指定路径）
2. 在「推流」页填入 **RTMP 地址**（如 `rtmp://live.example.com/app/`）和**串流密钥**（可选），点「测试连接」确认可用
3. 在「视频编码」等页设置编码参数，或直接选一套预设；调好后点「保存为预设」把整组设置存起来，之后可用预设栏的「重命名」调整名字
4. 左侧「+ 视频」添加文件（可多选），或拖入文件；同目录同名字幕会自动关联
5. 需要时展开某项的字幕与同步设置（点行内的字幕图标）：选择字幕轨、处理方式、音画与字幕延迟
6. 点「开始串流」（或按空格）
7. 串流中可拖动进度条跳转、点「下一个文件」跳过；日志面板可查看 FFmpeg 原始输出
8. 「停止」结束本次串流

### 常用 RTMP 服务器地址示例

| 平台 | 地址格式 |
| --- | --- |
| 本地 nginx-rtmp / SRS | `rtmp://127.0.0.1/live/` + 自定义密钥 |
| YouTube Live | `rtmp://a.rtmp.youtube.com/live2/` + 串流密钥 |
| Twitch | `rtmp://live.twitch.tv/app/` + 串流密钥 |
| 哔哩哔哩 | `rtmp://live-push.bilivideo.com/live-bvc/` + 串流密钥（含 `?` 参数，整段填入密钥框） |
| 抖音 / 视频号 | 由平台给出完整推流地址，把密钥部分填入密钥框即可 |

> 最终目标 = 地址原样 + 密钥原样（应用不插入任何分隔符），所以地址结尾是否带 `/` 由平台要求决定。

## 4. 已知限制与说明

- **跳转会重开一次 RTMP 会话**：RTMP 是单向直播流，已发送的帧无法撤回。跳转时缓冲里的内容排在观众还没看的内容后面，只能丢弃并重开一次会话，服务器会有约 1–3 秒的断流（观众端表现为一次重连）。缓冲有上限，所以跳转丢掉的通常只有十几秒。**文件自然播完不需要重开**：那时只切换下一个文件，观众连接不受影响。
- **「编码缓冲」不是观众端的延迟**：它限制的是编码最多能超前推流多少秒（12–300），目的是让编码偶尔变慢时不至于饿着推流端。代价是内存 —— 领先的每一秒都暂存在程序里，所以长缓冲会占更多内存。下限 12 秒是因为换文件本身就要几秒，设得更小会在每个文件边界断流。
- **正数延迟会在流开头留空档**：音视频/字幕延迟设为正值时内容整体后移，推流开头会有对应时长的空档。若只想修正音画不同步，建议使用负值（裁剪开头）。
- **内挂位图字幕（PGS / DVD / DVB）无法烧录**：只能处理文本字幕。应用会给出警告并跳过；在左侧列表里展开该项、选了位图轨并设为「烧录」时，面板会直接提示改用文本字幕。外挂 `.sup`/`.idx` 位图字幕则可以合成到画面上。
- **RTMP/FLV 基本不转发字幕轨**：除非服务器专门支持，请使用「烧录」模式。
- **Opus 在 FLV 中兼容性差**：默认使用 AAC；选择 Opus 时会给出警告。
- **封面图不算视频**：音乐/音频文件的专辑封面会被自动跳过，避免把封面当成画面推出去；如果文件因此只剩音频，日志会给出明确警告。
- **没有暂停**：恢复推流需要重开 RTMP 会话，与跳转一样会造成断流，因此不做。快捷键 `空格` 只用于开始串流。
- **程序目录必须可写**：状态存在程序目录的 `Data/` 下，不要把它放在只读位置（如 `C:\Program Files`）。放进只读目录时程序仍能运行，但设置与预设无法保存，界面会给出提示。
- **`MPEG-TS` / `Matroska` 不能作为 RTMP 目标**：这两种封装不是 RTMP 能承载的，选它们推流时会在开始写流时就失败（测试连接与正式推流表现一致）。
- **「实时节奏推流 `-re`」只在关闭双引擎后生效**：默认的双引擎下推流端始终按 1× 输出，该开关不起作用。

## 5. 数据与备份

所有状态（设置 / 播放列表 / 预设 / 日志）都写在**程序目录下的 `Data` 文件夹**，不使用系统漫游配置目录：

| 文件 | 内容 |
| --- | --- |
| `Data/settings.json` | FFmpeg 路径、界面语言与界面风格、播放列表栏宽度、当前会话设置 |
| `Data/playlist.json` | 播放列表，下次启动自动恢复 |
| `Data/presets.json` | 用户保存的预设（含推流目标） |
| `Data/Logs/` | 运行日志留存 |
| `Data/Cache/` | 缓存与临时数据 |

因为是绿色版，整个程序文件夹（含 `Data/`）可以**随意移动或复制到 U 盘**，换台机器解压后照常使用。

- **不导入任何外部状态**：首次启动不会从系统其它位置搬设置，一切都是新的
- **换机器继续用**：把整个程序文件夹一起复制过去
- **恢复出厂设置**：删掉 `Data/` 文件夹，下次启动会重建
