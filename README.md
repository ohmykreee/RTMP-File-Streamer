# RTMP 文件串流器 (RTMP File Streamer)

本地视频按播放列表顺序连续推流的桌面应用。视频（可带外挂或内挂字幕）按你的设置重新编码后推送出去，适合把本地片库当成一个 24 小时频道来播。

默认推流到 RTMP 服务器，同时支持 SRT、RTSP 与 WebRTC（WHIP）。

---

## 1. 功能

### 1.1 选择本地视频与字幕

- 「**+ 视频**」按钮多选视频文件，或把文件**直接拖进**播放列表；混入拖放的非视频文件会被自动忽略并记录日志
- 自动读取每个文件的时长、分辨率、帧率、音视频轨与**内挂字幕轨**
- 自动关联**同目录同名字幕**：`影片.srt`、`影片.zh-CN.ass`、`影片.forced.srt`，以及 `Subs/`、`字幕/` 子目录
- 每个文件可单独选择：使用哪条字幕轨（内挂第 N 条 / 外挂文件）、字幕处理方式、音视频延迟、字幕延迟
- 支持的外挂字幕：`.srt` `.ass` `.ssa` `.vtt` `.sub` `.idx` `.sup`。文本字幕可以烧录；`.sup`/`.idx` 等位图字幕能识别并关联，但**无法烧录进画面**，应用会给出警告并跳过

### 1.2 设置与预设

| 分类 | 可设置项 |
| --- | --- |
| **视频** | 编码格式（H.264 / H.265 / AV1 / 直接复制）、编码器（自动优选硬件，可指定 AMF / NVENC / QSV / libx264 / libx265 / SVT-AV1 / libaom）、码率控制（CBR / VBR / ABR / CRF）、码率、最大码率、缓冲区、CRF、preset、tune、profile、**分辨率（宽 / 高两个输入框 + 高度自适应勾选框）**、帧率、关键帧间隔、B 帧数、像素格式、关键帧独立 |
| **音频** | 编码格式（AAC / MP3 / Opus / 复制 / 丢弃）、码率、采样率、声道数、CBR / VBR、响度归一化（loudnorm −16 LUFS） |
| **字幕** | 处理方式（关闭 / **烧录进画面** / 作为独立轨道复制）、样式来源（保留原 ASS 样式 / 强制覆盖 / 纯文本）、字体、字号、颜色、描边、阴影、垂直边距、对齐方式、粗体/斜体 |
| **输出** | 推流地址与协议、串流密钥（可选、点状显示）、推流传输方式、测试连接与命令预览、**缓冲推流开关与编码提前量（12–300 秒）**、实时节奏、播放列表循环、断线重连间隔与次数、丢弃迟到帧、追加自定义 FFmpeg 参数、obs-websocket 兼容控制接口 |
| **高级** | **界面设置**（语言、界面风格：亮色 / 暗色 / 跟随系统）、日志留存与**调试输出开关**（关闭后只写 info 及以上）、FFmpeg 路径/版本/编码器可用性 |
| **预设** | 把视频、音频、字幕、输出四个会话选项卡的设置保存为命名预设；另有 5 套内置预设 |

**码率单位**：视频码率、最大码率与缓冲区有 `kbps / Mbps` 下拉框，随手写哪种都行，不会把数值当成另一个数量级；音频码率按 kbps 填写。

**分辨率**：

- 关闭「缩放输出」= 保持源分辨率
- 打开后填写**宽度**与**高度**两个框，或从下拉选择预设（4K / 2K / 1080p / 900p / 720p / 480p / 360p）
- 宽高会自动取偶（H.264/H.265 的 4:2:0 编码要求偶数尺寸）
- 勾选「**高度自适应**」→ 高度框变为禁用并显示「自动」，由 ffmpeg 按源画面比例算好

**CRF 模式**：最大码率仍然生效，作为码率上限，避免推流码率失控；界面在 CRF 下也会显示该字段。

对某个文件单独选轨道：展开它的「字幕与同步设置」，可选内挂第 N 条或指定外挂文件。

#### 预设

- 顶部预设栏：下拉选择（内置预设 / 我的预设分组）+「保存为预设」+「**重命名**」+「删除」+「数据目录」
- **重命名**只换名称：预设 id、里面保存的设置、当前选中状态都不变；内置预设不能重命名、不能删除
- 保存时把**视频、音频、字幕、输出四个会话选项卡的设置**写入一个命名预设；高级页的语言、外观、日志、FFmpeg 路径不进入预设
- **套用内置预设只改变编码相关设置，不会覆盖你的推流地址、串流密钥与 obs-websocket 配置**
- **用户预设会明文保存推流目标**：套用用户预设会完整还原整组配置，包括往哪里推流
- 同名保存用户预设即覆盖；应用预设会一次性替换对应的会话设置
- 手动改动任意设置后，下拉框自动回到「（自定义）」，不会假装仍匹配某个预设

### 1.3 推流到流媒体服务器

- **协议决定地址格式、封装与串流密钥的用法**：

  | 协议 | 地址示例 | 串流密钥的用途 |
  | --- | --- | --- |
  | RTMP / RTMPS | `rtmp://live.example.com/app/` | 直接追加到地址末尾 |
  | SRT | `srt://live.example.com:9000` | 作为 `passphrase` 参数发送 |
  | RTSP | `rtsp://live.example.com:8554/live` | 直接追加到地址路径 |
  | WebRTC / WHIP | `https://live.example.com/whip/endpoint` | 作为 Bearer 令牌发送 |

- 地址框**失焦时自动识别协议**并切换下拉；识别后仍可手动改。地址与协议不匹配时无法开始或测试，应用会提示要求的地址格式
- 所有输入框中，**地址与数字框在离开输入框时生效**；串流密钥、额外参数、文本与颜色即时生效
- 地址框可以留空（下方会提示「地址为空，无法开始串流。」），空着时「开始串流」不可用 —— 不会自动把示例地址填回去
- 串流密钥输入框**点状显示**（可点「显示」临时查看）；密钥明文保存在本地设置与预设中，**界面与日志不显示完整目标**（只显示服务器地址，密钥部分以 `***` 代替）
- 封装由协议自动决定（RTMP→FLV，SRT→MPEG-TS，RTSP/WHIP 使用各自协议），没有单独的容器选项
- 内置 **「测试连接」**：按当前各选项卡的编码设置推送 5 秒测试画面，直接给出服务器返回的原文与诊断结论；服务器无响应时按时退出，不会卡住界面
  - 测试与正式推流共用编码器、码率控制、采样率、声道数、响度归一化、帧率、关键帧间隔、像素格式、协议与自定义参数，所以「测试通过」意味着这组编码参数能推上去，而不只是地址通
  - 测试画面是合成画面：启用缩放时按目标尺寸生成并最高压到 1280×720，未启用缩放时用 640×360；音视频设为「直接复制」或「不要音频」时在测试里没有可复制的源，会回退到软件编码或真的不发音频轨；字幕烧录与字幕复制不在测试范围内。这些差异会在结果里列出
- 内置 **「查看 FFmpeg 命令」**：可复制当前设置生成的命令行。开启缓冲推流时实际会运行编码器与推流器两个进程，预览显示的是等价的单进程命令，并会注明
- 断线自动重连（次数/间隔可配）：单进程管道会在断点附近回退后续传；缓冲推流会从观众当前的位置重建会话
- **串流进行中锁定设置与播放列表编辑**：编码命令在开始时已按当时参数生成，串流中设置面板、预设栏和播放列表的增删/排序/清空/字幕编辑都会冻结；跳转、跳过、停止与查看日志保持可用，停止后自动解锁

### 1.4 串流进度与跳转

- 播放列表**整条**渲染为进度条：每个文件一段，已播完的段落变绿、正在播的高亮，段间有分隔线
- **可拖动**：拖动时只显示目标文件名；松开即跳到该文件的**开头**（直播流无法回退已发送的帧，应用也不提供文件内跳转）
- 松手在**当前文件内是空操作**
- 开启缓冲推流时，进度条底边缘会多一条**细绿条**，表示编码已经跑到哪。蓝条与绿条之间的距离是编码提前量，也就是跳转需要丢弃的部分 —— 所以跳转会重开一次发布会话
- **「下一个文件」** 立即切到下一段（快捷键 `Ctrl+→`）
- 每一行右侧的图标按钮，从左到右是：**从该文件开始串流 / 跳转到此文件**、字幕与同步设置、移除（鼠标悬停会显示名称；串流进行中前两项中的编辑动作被锁定）
- 条下方是一行小字读数：当前文件与位置/时长、编码速度/码率/fps、缓冲领先、实测网络速率、丢帧与已运行时长；空闲时不显示这些统计
- 串流结束（播完整个列表，或手动停止）后进度归零，等待下一次串流

### 1.5 多文件顺序串流

- 播放列表可拖拽排序、逐项删除、一键清空
- 播放列表与设置之间是**可拖动的分栏**：拖中间的分隔条即可加宽队列
- 播完一个文件后**自动**按顺序进入下一个，直到列表结束（或按设置循环）
- 每项状态实时标注：待串流 / 准备中 / 推流中 / 已完成 / 已跳过 / 错误
  - 这些状态描述的是**观众看到了哪一段**，不是编码跑到哪一段：编码会提前跑在前面，所以已编码但还没播出的文件显示「准备中」
- 播放列表与全部设置**自动保存**，下次启动自动恢复并重新校验文件

### 1.6 界面设置（语言与外观）

- 语言按钮在**顶栏最右侧**（地球图标 + 当前语言代码），点开列出 中文 / 日本語 / English，当前项带勾选；「高级 → 界面设置」里也有同一个语言选择
- **首次启动按系统语言自动选择**：中文（简体或繁体）→ 中文；日语 → 日语；**其他所有语言 → 英文**
- 显式切换后**立即生效并保存**，之后不再跟随系统语言；没有显式切换过时，启动会继续跟随系统语言
- 语言覆盖界面、窗口标题、原生文件对话框，以及**运行日志与错误提示**：切换后新的日志行即为所选语言
- **界面风格**：亮色 / 暗色 / **跟随系统（默认）**。「跟随系统」时随操作系统的深浅色设置实时切换，窗口底色也一起变
- 语言与界面风格属于**应用设置**：不写入播放列表，也不写入预设 —— 套用预设不会改变界面语言或外观
- 串流进行中语言与外观设置与其他设置一起锁定

### 1.7 其他

- 运行日志面板（按 调试/信息/警告/错误/FFmpeg 过滤、自动滚动、可清空；筛选无结果时会单独提示）
- **日志留存**：运行日志同步写入 `Data/Logs/session-*.log`。单个文件超过 4 MB 会滚动到新文件；总量超过 12 MB 或文件数超过 20 个时自动删除最旧的文件
- 硬件编码器**实测可用性检测**（不只是列出名称，而是真的编码几帧验证驱动能不能用）
- 快捷键：`空格` 开始串流（焦点在按钮/开关/输入框上时不会抢占），`Ctrl+→` 下一个文件
- 串流中关闭窗口会弹出确认：选择停止并关闭，或继续串流

## 3. 使用步骤

1. 启动应用，确认右上角显示 FFmpeg 版本号（若显示「未找到 FFmpeg」，到「高级」页手动指定路径）
2. 在「推流」页选择协议并填入地址与串流密钥（可选），点「测试连接」确认可用
3. 在「视频编码」等页设置编码参数，或直接选一套预设；调好后点「保存为预设」把整组会话设置存起来，之后可用预设栏的「重命名」调整名字
4. 左侧「+ 视频」添加文件（可多选），或拖入文件；同目录同名字幕会自动关联
5. 需要时展开某项的字幕与同步设置（点行内的字幕图标）：选择字幕轨、处理方式、音画与字幕延迟
6. 点「开始串流」（或按空格）
7. 串流中可拖动进度条跳转、点「下一个文件」跳过；日志面板可查看 FFmpeg 原始输出
8. 「停止」结束本次串流

### 常用服务器地址示例

| 平台 / 协议 | 地址格式 |
| --- | --- |
| 本地 nginx-rtmp / SRS（RTMP） | `rtmp://127.0.0.1/live/` + 自定义密钥 |
| YouTube Live（RTMP） | `rtmp://a.rtmp.youtube.com/live2/` + 串流密钥 |
| Twitch（RTMP） | `rtmp://live.twitch.tv/app/` + 串流密钥 |
| 哔哩哔哩（RTMP） | `rtmp://live-push.bilivideo.com/live-bvc/` + 串流密钥（含 `?` 参数，整段填入密钥框） |
| SRT 接收端 | `srt://receiver.example.com:9000` + 口令 |
| RTSP 服务器 | `rtsp://receiver.example.com:8554/live` + 密钥（按服务器要求） |
| WHIP 端点 | `https://receiver.example.com/whip/endpoint` + 令牌 |

> RTMP/RTSP 的最终目标 = 地址原样 + 密钥原样（应用不插入任何分隔符），所以地址结尾是否带 `/` 由平台要求决定。

## 4. 已知限制与说明

- **跳转会重开一次发布会话**：RTMP 是单向直播流，已发送的帧无法撤回。跳转时缓冲里的内容排在观众还没看的内容后面，只能丢弃并重开一次会话，服务器会有约 1–3 秒的断流（观众端表现为一次重连）。跳转实际丢弃的缓冲量取决于「编码提前量」设置，最大可接近 5 分钟。**默认开启缓冲推流时，文件自然播完只重启编码器，观众连接不受影响；关闭缓冲推流后，每个文件都会重新发布会话。**
- **编码提前量不是观众端的延迟**：它限制的是编码最多能超前推流多少秒（12–300），目的是让编码偶尔变慢时不至于饿着推流端。代价是内存 —— 领先的每一秒都暂存在程序里，所以更大的提前量会占更多内存。下限 12 秒是因为换文件本身就要几秒，设得更小会在每个文件边界断流。
- **正数音视频延迟会在流开头留空档**：音视频延迟设为正值时内容整体后移，推流开头会有对应时长的空档；只想修正音画不同步时建议使用负值（裁剪开头）。字幕延迟只影响烧录的文本字幕；复制字幕轨或位图字幕时该设置会被忽略并给出警告。
- **位图字幕无法烧录**：内挂 PGS / DVD / DVB 与外挂 `.sup`/`.idx` 都只能作为字幕轨处理，不能烧进画面。请改用文本字幕；在左侧列表里展开该项、选了位图轨并设为「烧录」时，面板会直接提示。
- **独立字幕轨只在 MPEG-TS 等支持的封装中可用**：FLV 与 WebRTC 不承载独立字幕轨；需要字幕时请使用「烧录进画面」。缓冲推流下也不支持复制字幕轨。
- **直接复制需要源编码与目标封装兼容**：例如 VP9/AV1 视频复制进 FLV、AC-3/DTS 音频复制进 FLV 都不受支持；应用会给出警告。AV1 视频也不能经 MPEG-TS 中转，开启缓冲推流时会自动改用单进程，SRT 等 MPEG-TS 目标则不支持 AV1。
- **Opus 在 FLV 中兼容性差**：默认使用 AAC；选择 Opus 时会给出警告。WebRTC（WHIP）则要求 Opus 音频与 H.264 视频。
- **缺少音轨或视频轨的文件会自动补轨**：源文件没有音频（且音频编码不是「直接复制」或「不要音频」）时，按当前音频设置编码一路静音；没有可用视频（且视频编码不是「直接复制」）时，按当前视频设置编码黑场画面（未开启缩放时用 1280×720）。这样推出去的始终是完整的两路，不会被服务器当成单流拒绝
- **封面图不算视频**：音乐/音频文件的专辑封面会被自动跳过，不会把封面当成画面推出去；整份文件只有封面时按上一条推送黑场画面
- **没有暂停，也没有文件内跳转**：恢复推流需要重开发布会话，与跳转一样会造成断流，因此不做。快捷键 `空格` 只用于开始串流。
- **实时节奏与丢弃迟到帧只在关闭缓冲推流后生效**：缓冲推流下由推流器固定按 1× 输出，这两个开关在界面上会说明其限制。
- **程序目录必须可写**：状态存在程序目录的 `Data/` 下，不要把它放在只读位置（如 `C:\Program Files`）。放进只读目录时程序仍能运行，但设置与预设无法保存，日志里会给出错误提示。
- **播放列表使用绝对路径**：移动程序文件夹后，设置与预设仍可用，但播放列表里的文件如果换了盘符或机器会失效，需要重新添加。

## 5. 数据与备份

所有状态（设置 / 播放列表 / 预设 / 日志）都写在**程序目录下的 `Data` 文件夹**，正常情况下不使用系统漫游配置目录：

| 文件 | 内容 |
| --- | --- |
| `Data/settings.json` | FFmpeg 路径、界面语言与界面风格、播放列表栏宽度、当前会话设置 |
| `Data/playlist.json` | 播放列表，下次启动自动恢复 |
| `Data/presets.json` | 用户保存的预设（含明文推流目标） |
| `Data/Logs/` | 运行日志留存 |
| `Data/Cache/` | 缓存与临时数据 |

> `settings.json` 与 `presets.json` 明文保存推流地址和串流密钥，请勿公开分享、上传仓库或随程序一起发给他人。

因为是绿色版，整个程序文件夹（含 `Data/`）可以**复制或移动到 U 盘**，换台机器解压后照常使用；播放列表中的绝对路径需要保持有效，或重新添加文件。

- **不导入任何外部状态**：首次启动不会从系统其它位置搬设置，一切都是新的
- **换机器继续用**：把整个程序文件夹一起复制过去
- **恢复出厂设置**：删掉 `Data/` 文件夹，下次启动会重建
