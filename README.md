# RTMP 文件串流器 (RTMP File Streamer)

以 **FFmpeg 为后端**的本地文件直播推流桌面应用。把本地视频（可选外挂/内挂字幕）按设定重新编码后，推送到 RTMP 服务器，并按播放列表顺序连续串流多个文件。

- **技术栈**：Electron 44 + React 19 + TypeScript + Vite（electron-vite 构建），主进程直接驱动 FFmpeg 子进程
- **跨平台**：Windows（已在本机验证并打包）/ macOS / Linux 均可构建运行
- **后端**：调用系统 FFmpeg（自动探测，也可手动指定），不修改也不重打包 FFmpeg

---

## 1. 功能

### 1.1 选择本地视频与字幕

- 「**+ 视频**」按钮多选视频文件，或把文件**直接拖进**播放列表（Electron 新版本已移除 `File.path`，拖入路径通过预加载桥 `webUtils.getPathForFile` 解析；混入拖放的非视频文件会被自动忽略并记录日志）
- 自动对每个文件运行 `ffprobe`，读取时长、分辨率、帧率、音视频轨、**内挂字幕轨**
- 自动关联**同目录同名字幕**：`影片.srt`、`影片.zh-CN.ass`、`影片.forced.srt`，以及 `Subs/`、`字幕/` 子目录
- 每个文件可单独选择：使用哪条字幕轨（内挂第 N 条 / 外挂文件）、字幕处理方式、音视频延迟、字幕延迟
- 支持的外挂字幕：`.srt` `.ass` `.ssa` `.vtt` `.sub` `.idx` `.sup`

### 1.2 编码设置

| 分类 | 可设置项 |
| --- | --- |
| **视频** | 编码格式（H.264 / H.265 / AV1 / 直接复制）、编码器（自动优选硬件，可指定 AMF / NVENC / QSV / libx264 / libx265 / SVT-AV1 / libaom）、码率控制（CBR / VBR / ABR / CRF）、码率、最大码率、缓冲区、CRF、preset、tune、profile、**分辨率（宽 / 高两个输入框 + 高度自适应勾选框）**、帧率、关键帧间隔、B 帧数、像素格式、重复 SPS/PPS 头 |
| **音频** | 编码格式（AAC / MP3 / Opus / 复制 / 丢弃）、码率、采样率、声道数、CBR / VBR、响度归一化（loudnorm −16 LUFS） |
| **字幕渲染嵌入** | 处理方式（关闭 / **烧录进画面** / 作为独立轨道复制）、样式来源（保留原 ASS 样式 / 强制覆盖 / 纯文本）、字体、字号、颜色、描边、阴影、垂直边距、对齐方式、粗体/斜体 |
| **输出** | RTMP 地址、串流密钥（可选、点状显示）、容器（FLV / MPEG-TS / Matroska）、实时节奏 `-re`、播放列表循环、断线重连间隔与次数、文件间停顿、跳转精度、丢弃迟到帧、追加自定义 ffmpeg 参数 |
| **预设** | 把以上全部设置保存为命名预设，存放在程序同目录的 `config/presets.json`；另有 5 套内置预设 |

**码率单位**：所有码率输入框右侧都有 `kbps / Mbps` 下拉框。内部统一以 kbps 存储并传给 ffmpeg，切换单位只是换一种写法（3200 kbps ⇄ 3.2 Mbps），不会把数值当成另一个数量级。

**分辨率**：
- 关闭「缩放输出」= 保持源分辨率（不添加 `scale` 滤镜）
- 打开后填写**宽度**与**高度**两个框，或从下拉选择预设（4K / 2K / 1080p / 900p / 720p / 480p / 360p）
- 勾选「**高度自适应**」→ 高度框变为禁用并显示「自动」，由 ffmpeg 按源画面比例计算（等价于 `scale=宽:-2`），避免手算非偶数高度导致编码失败

**轨道选择**：内挂字幕通过 `subtitles` 滤镜的 `si=` 参数精确指定第几条轨道；外挂字幕作为独立输入由 libass 直接读取。

#### 预设

- 顶部预设栏：下拉选择（内置预设 / 我的预设分组）+「💾 保存为预设」+「删除」+「📂 配置目录」
- 保存时把**视频编码、音频编码、字幕、输出、高级五个选项卡的全部设置**写入一个命名预设
- **推流目标（RTMP 地址与串流密钥）随预设一起明文保存**：套用预设会完整还原整组配置，包括往哪里推流
- 同名保存即覆盖；应用预设会一次性替换全部设置
- 手动改动任意设置后，下拉框自动回到「（自定义）」，不会假装仍匹配某个预设

存储位置：所有状态（设置 / 播放列表 / 预设）都写在**程序目录下的 `Data` 文件夹**，不使用系统漫游配置目录：

| 文件 | 内容 |
| --- | --- |
| `Data/settings.json` | ffmpeg 路径、当前会话设置 |
| `Data/playlist.json` | 播放列表，下次启动自动恢复 |
| `Data/presets.json` | 用户保存的预设（含推流目标） |
| `Data/Logs/` | 运行日志留存（JSONL 会话文件，总量上限 12 MB，超出自动清理最旧文件） |
| `Data/Cache/` | Chromium/Electron 的缓存与日志（与数据分开存放） |

`Data` 文件夹在需要时自动创建；预设栏的「📂 数据目录」按钮可直接打开它。若该位置不可写，界面会标红提示。

因为状态就在程序目录内，整个 `release/win-unpacked` 文件夹可以**随意移动或复制到 U 盘**，换台机器解压后照常使用（已实测移动后仍能正常读写）。从旧版本升级时，首次启动会自动把 `%APPDATA%\RTMP File Streamer` 里的设置、队列与预设迁移过来，并在日志中说明迁移了哪些文件。

### 1.3 推流到 RTMP 服务器

- **推流目标 = RTMP 地址 + 串流密钥，直接拼接**（应用不再插入 `/`，仅当两者叠出 `//` 时收敛为一个）。地址按平台要求自带结尾斜杠；**串流密钥可选**，留空则直接推送地址本身
- 串流密钥输入框**点状显示**（可点「显示」临时查看）；密钥明文保存在本地设置/预设中，界面与信息级日志均不显示完整目标，**完整推流目标只出现在调试（debug）日志里**
- 输出 FLV，带 `no_duration_filesize`、`+cgop`（关键帧重复 SPS/PPS）、单调时间戳
- 内置 **「测试连接」**：推送 5 秒测试画面，直接给出服务器返回的原文与诊断结论；测试进程有硬超时，服务器无响应时按时报错退出，不会卡住界面
- 内置 **「查看 ffmpeg 命令」**：可复制当前设置生成的完整命令行
- 断线自动重连（次数/间隔可配），从断点略微回退后续传
- **串流进行中锁定全部设置**：编码命令在开始时已按当时参数生成，串流中设置面板、预设栏与播放列表的编辑项都会冻结（添加文件、跳转不受影响），停止后自动解锁

### 1.4 串流进度与跳转

- 播放列表**整条**渲染为进度条：每个文件一段，已播完的段落变绿、正在播的高亮，段间有分隔线
- **可拖动**：拖动时显示目标文件名与时间，松开即跳转；松手在**当前文件内是空操作**（直播流无法回退已发送的帧，文件内跳转已移除），松手在其它文件上则跳到那个文件
- **双引擎推流时，大进度条的底边缘会多一条细绿条**，表示编码进程已经跑到哪：它和上面的蓝条是同一条时间轴，所以画在同一根条里。蓝条与绿条之间的距离就是"缓冲领先"，也就是跳转需要丢弃的部分 —— 因此跳转会重开一次 RTMP 会话
- **「⏭ 下一个文件」** 立即切到下一段（快捷键 `Ctrl+→`）
- 每个文件也可单独点「▶ 从此开始」
- 进度条下方显示**当前总进度百分比**与缓冲领先；上方状态行显示当前文件位置/时长、编码速度、码率、fps、丢帧、重连次数、已运行时长

### 1.5 多文件顺序串流

- 播放列表可拖拽排序、逐项删除、一键清空
- 播完一个文件后**自动**按顺序进入下一个，直到列表结束（或按设置循环）
- 每项状态实时标注：待串流 / 准备中 / 推流中 / 已完成 / 已跳过 / 错误
  - 这些状态**永远反映推流进度，不反映编码进度**：双引擎下编码进程可能已经跑完整个列表，但列表里仍只有当前正在播出的那一项是「推流中」，其余已编码未播出的显示「准备中」。仅靠编码完成就把条目标成「已完成」会让整个队列在开播几秒内全部变绿
- 播放列表与全部设置**自动保存**，下次启动自动恢复并重新校验文件

### 1.6 其他

- 运行日志面板（按 信息/警告/错误/FFmpeg 过滤、自动滚动、可清空）
- **日志留存**：全部运行日志同步写入 `Data/Logs/session-*.log`（JSONL，含时间戳与级别，引擎还会标注所属文件）。日志面板可直接打开日志目录并显示当前占用；目录总量超过 12 MB 或超过 20 个会话文件时自动删除最旧文件，单个文件超过 4 MB 自动滚动，无需手动清理
- 硬件编码器**实测可用性检测**（不只是列出名称，而是真的编一帧验证驱动）
- 探测/选流诊断：每个文件串流前会把 ffprobe 探到的**完整流列表（含封面图标记）与实际选用的音视频流**写进调试日志，"推出去只有音频"这类问题可以直接从日志定位
- 快捷键：`空格` 开始串流，`Ctrl+→` 下一个文件

## 3. 开发与构建

```bash
pnpm install          # 安装依赖
pnpm dev              # 开发模式（热重载）
pnpm typecheck        # 类型检查
pnpm build            # 编译主进程/预加载/渲染进程到 out/
pnpm start            # 用编译产物启动（不弹 DevTools）
```

### 打包

```bash
pnpm dist             # 生成免安装目录版 release/win-unpacked/
```

产物只有一个：`release/win-unpacked/`，直接运行其中的 `RTMPFileStreamer.exe`。**不生成单文件便携 exe，也不生成 NSIS 安装包**，因为程序状态写在自身目录的 `Data/` 里 —— 整个文件夹就是完整可移动的绿色版。

macOS / Linux 的目标同样配置为 `dir`，在对应平台执行 `electron-builder --mac` / `--linux` 即可。

### 随包附带 FFmpeg（可选）

默认**不**打包 FFmpeg（GPL 许可，且体积大）。若需要离线分发：把 `ffmpeg.exe`、`ffprobe.exe` 放进项目根的 `bin/` 目录，`pnpm dist` 会自动复制到 `resources/bin`，运行时优先使用它。

## 4. 使用步骤

1. 启动应用，确认右上角显示 FFmpeg 版本号（若显示「未找到 FFmpeg」，到「高级」页手动指定路径）
2. 在「📡 输出 / RTMP」填入 **RTMP 地址**（如 `rtmp://live.example.com/app/`）和**串流密钥**（可选），点「测试连接」确认可用；完整推流目标 = 地址 + 密钥直接拼接
3. 在「🎞 视频编码」等页设置编码参数（码率旁可选 kbps/Mbps，分辨率可填宽高或勾选高度自适应），或直接选一套预设；调好后点「💾 保存为预设」把整组设置存起来
4. 左侧「+ 视频」添加文件（可多选），或拖入文件；同名同目录字幕会自动关联
5. 需要时展开某项的「字幕/同步」：选择字幕轨、处理方式、音画与字幕延迟
6. 点「▶ 开始串流」（或按空格）
7. 串流中可拖动进度条跳转、点「⏭ 下一个文件」跳过；日志面板可查看 FFmpeg 原始输出
8. 「⏹ 停止」结束本次串流

### 常用 RTMP 服务器地址示例

| 平台 | 地址格式 |
| --- | --- |
| 本地 nginx-rtmp / SRS | `rtmp://127.0.0.1/live/` + 自定义密钥 |
| YouTube Live | `rtmp://a.rtmp.youtube.com/live2/` + 串流密钥 |
| Twitch | `rtmp://live.twitch.tv/app/` + 串流密钥 |
| 哔哩哔哩 | `rtmp://live-push.bilivideo.com/live-bvc/` + 串流密钥（含 `?` 参数，整段填入密钥框） |
| 抖音 / 视频号 | 由平台给出完整推流地址，把密钥部分填入密钥框即可 |

> 拼接规则：最终目标 = 地址原样 + 密钥原样（应用不插入任何分隔符），因此地址结尾是否带 `/` 由平台要求决定。

## 5. 已知限制与说明

- **跳转会重开一次 RTMP 会话**：RTMP 是单向直播流，已发送的帧无法撤回。跳转时**双引擎的缓冲会被丢弃并重开一次发布会话**，因为缓冲里的内容排在观众还没看的内容后面，而已发布的时间轴无法回退；服务器会有约 1–3 秒的断流（观众端表现为一次重连）。缓冲是有上限的（见下一条），所以跳转丢掉的通常只有十几秒。**文件自然播完不需要重开**：那时推流端已经把交付的内容播完，只重启编码进程，RTMP 会话与观众连接都不受影响。
- **双引擎推流与「编码缓冲」**：默认开启「双引擎推流」——编码进程全速编码、推流进程按 1× 稳定输出，编码偶尔跟不上时由缓冲吸收。此时「编码缓冲」是**编码最多领先推流的秒数**：超过这个领先量，应用会暂停编码进程的输出（管道回压）等推流追上，因此缓冲不会随播放列表增长——这一点很关键，因为领先的每一秒都留在内存里（约 码率/8 KB，已经播出的部分随推流进程读取即时释放）。它**不是观众端的延迟**：推流进程才是时钟，收到多少就按 1× 播多少。下限 12 秒是实测出来的：换文件时上一段编码结束到下一段产出首个数据包要 5.8–7.5 秒，缓冲小于这个值就会在每个文件边界断流；上限 300 秒（5 分钟，4 Mbps 下约 150 MB），够扛住编码临时变慢。数值在**输入框失焦时**才夹取。关闭双引擎后该输入框不可用，回到单进程管道，节奏由推流端决定。
- **正数延迟会在流开头留空档**：音视频/字幕延迟设为正值时，内容整体后移，推流开头会有对应时长的空档。若只想修正音画不同步，建议使用负值（裁剪开头）。
- **内挂位图字幕（PGS / DVD / DVB）无法烧录**：libass 只处理文本字幕。应用会给出警告并跳过；外挂 `.sup`/`.idx` 位图字幕则通过 `overlay` 滤镜合成。
- **RTMP/FLV 基本不转发字幕轨**：除非服务器专门支持，请使用「烧录」模式。
- **Opus 在 FLV 中兼容性差**：默认使用 AAC；选择 Opus 时会给出警告。
- **封面图不算视频**：音乐/音频文件的专辑封面是 `attached_pic` 视频流，会被自动跳过，避免把封面当成画面推出去；如果文件因此只剩音频，日志会给出明确警告。
- **暂停功能已移除**：恢复推流需要重开 RTMP 会话，与跳转一样会造成断流，因此不做。快捷键 `空格` 只用于开始串流。
- **程序目录必须可写**：状态存在程序目录的 `Data/` 下，因此不要把它放在只读位置（如 `C:\Program Files`）。放进只读目录时程序仍能运行，但设置与预设无法保存，界面会给出提示。
- **切换设置选项卡不会挪动进度条**：工作区高度固定、只有设置面板内部滚动，播放/进度区域的位置和高度始终一致。

## 7. 自动化验证

```bash
pnpm test                # 默认跑 test:unit
pnpm run test:unit       # 非 Electron 全部：命令构建 + 真实转码/字幕渲染 + 本地推流 + obs-websocket
pnpm run test:e2e        # Electron 全部套件（ui → features → presets → layout → datadir → engine）
pnpm run test:e2e ui     # 只跑指定套件，可写多个：node .test/e2e.mjs ui presets
pnpm run test:ci         # 类型检查 → 构建 → test:unit → test:e2e
```

`test:unit` 会按需生成 fixture、打包被测模块，再跑断言；`test:e2e` 需要先 `pnpm build`（`test:ci` 已包含）。两套都会在首个失败处停下并给出失败项，`e2e` 还带看门狗：某个套件超时会被杀掉并以非零码报告，不会挂住整轮。

测试用 `ffmpeg -listen 1` 充当下游 RTMP 服务器，因此不需要外部流媒体服务。所有端到端测试都装有**看门狗**（超时即杀掉残留进程并以退出码 3 报告卡住的步骤），UI 驱动全部走 CDP 程序化调用；测试启动的应用以 `STREAMER_E2E=1` 运行——窗口移出屏幕并开启点击穿透，物理鼠标不会干扰测试。

已验证内容（`pnpm run test:unit` 88 项 + `pnpm run test:e2e` 全绿）：

- **命令层与转码**：媒体探测、外挂字幕自动关联、字幕滤镜转义（Windows 盘符冒号、样式逗号）、分辨率三态（关闭 / 显式宽高 / 高度自适应）与非法几何回退、CBR/VBR/CRF 参数、硬件编码器与像素格式映射、跳转与音画偏移的时间戳语义、RTMP 地址拼接，并**实际执行生成的命令**再解码校验产出
- **字幕渲染**：外挂字幕与**内嵌字幕轨**各跑一次烧录，抽取画面用 `signalstats` 验证字幕区域出现高亮字形像素（YMAX 235，中文正常渲染，见 `docs/subtitle-burn-in.png`）；命令层另校验内嵌轨用的是媒体文件路径 + 字幕流序号（`si` 按字幕流计数，不是 ffprobe 的绝对流号，选第二条内嵌轨必须是 `si=1`）
- **编码缓冲（双引擎）**：用同一个 45s 素材、同一段编码参数跑两次真实播放（12s 与 24s 上限），要求实测领先量被压在设定值附近（含一个 `-progress` 周期的过冲）且**更大的设定确实允许更深的缓冲**，同时推流进程在编码被暂停期间持续按 1× 出流——这正是"上限真的生效、而不是随便编完整个列表"的证据
- **本地推流**：`ffmpeg -listen 1` 接收真实推送，校验进度单调递增、`-re` 实时节奏、收到可解码的音视频

- **引擎 20 项**：两文件自动续播（20s + 15s 全部送达并解码）、进度单调递增、`-re` 实时节奏、跳转后仅重推剩余 8 秒、跳过目标完整送达、无错误日志
